This folder contains the project knowledge layer for Developer OS.

It is designed to keep the product understandable, maintainable, and scalable as the platform grows.

## Documentation map

- `architecture.md` — system overview, responsibilities, and technical structure
- `developer-workflows.md` — practical workflow patterns for day-to-day engineering work

## Purpose of the documentation

The goal of this folder is to make Developer OS feel like a real ecosystem, not just a codebase.

It captures:
- system design ideas
- engineering workflows
- implementation direction
- project vision and structure

## Thinking behind the project

Developer OS is meant to become a unified environment where developers can manage:
- projects
- references
- workflows
- tools
- notes and context
- execution momentum

## Documentation philosophy

The documentation is intentionally built around three principles:

### 1. Clear structure
The project should be easy to understand for contributors and future maintainers.

### 2. Workflow-first thinking
The system is not only about data; it is about how developers actually work.

### 3. Long-term ecosystem growth
The docs help the project evolve from an MVP into a durable developer platform.

## Recommended reading order

1. `architecture.md`
2. `developer-workflows.md`
3. root `PROJECT.md`
4. root `README.md`

This helps new contributors understand both the vision and the implementation direction quickly.
